# extreme-proofs-with-llm

Sampling Conway and Shipman's *extreme proofs* with a language model:
generate proofs of one theorem under prompts that each maximise one
attribute, embed them, and see where they land relative to a labelled
reference set of known proofs.

Write-up: **[Not all extremal directions are the same kind of
thing](https://jonathankeogh.com/writing/...)**

## The question

Conway and Shipman (*Extreme Proofs I: The Irrationality of √2*, Math.
Intelligencer 35(3), 2013) treat proofs as points in a space whose
coordinates are attributes — brevity, elementarity, generality, visuality,
weight of machinery — with *extreme proofs* as the vertices. They built
their space by hand from proofs in the literature. This asks whether a
language model can be used to sample it.

Short answer: the attributes are not coordinates of one space. Three select
among known arguments, one leaves the known set entirely, and one only
re-renders an argument you already had. See the write-up.

## The corpus

`proofs_primes.jsonl` — 558 proofs of the infinitude of primes, generated by
`claude-opus-5` (medium effort, pinned snapshot, one model throughout) via
the Message Batches API. Three arms:

| arm | n | grid |
|---|---|---|
| technique | 300 | 5 techniques × 6 languages × 2 styles × 5 samples |
| extreme | 150 | 5 extremal criteria × 6 languages × 5 samples |
| scope | 108 | 6 statements × 6 languages × 3 samples |

Technique arm techniques: Euclid, Euler product, Fürstenberg, Erdős
counting, Fermat numbers. Extreme arm criteria: brevity, elementarity,
generality, visuality, machinery.

The extreme arm is the 5 criteria this corpus was first generated with; the
shared set in `config.py` is 8, so three cells here are empty and one was
generated from a wording since replaced. `uv run config.py` prints which,
for all three theorems at once, and `prune.py` removes the stale records so
`--submit` can refill them. The analysis in this README predates that.

Languages: en, fr, de, es, zh, ja. Chinese and Japanese are deliberate — a
European-only grid lets shared Latin roots give a multilingual embedding an
easy ride.

Each record stores its full prompt, model, effort, token cap and usage, so
the generation is auditable from the file. Treat `proofs_primes.jsonl` as
immutable; version it rather than mutating it.

**One corpus intervention, disclosed.** The first run capped output at
10,000 tokens and produced 28 truncations, 83% of them in `generality`. The
cause was a prompt clause asking the model to "make that extension visible"
— a deliverable beyond the proof. Diagnosed from the prompt text before
reading any output, clause removed, cap raised, those 30 records
regenerated. `proofs_primes.pre-generality-fix.jsonl` is the pre-fix corpus, kept
so the change is auditable. Records from the first run carry no `max_tokens`
field and the regenerated ones carry `max_tokens: 32000`, so the fix is
checkable directly from the corpus file (33 records: 30 `generality`, 3
`machinery`). Details in the write-up.

## Layout

```
config.py          every constant that must not vary between the three
                   theorems: model, effort, token cap, languages, styles,
                   sample counts, and the 8 extremal DIRECTIONS. Run it to
                   print what the corpora actually contain against what it
                   specifies -- it re-derives that from the stored prompts,
                   not from this file's own claims
generate_primes.py batch generation via the Message Batches API; --dry-run,
                   --submit, --collect; resumes by diffing the grid against
                   proofs_primes.jsonl; --scope-arm adds the centre cell
                   and the scope ladder
generate_sqrt2.py  the same design on Conway and Shipman's own theorem, the
                   irrationality of sqrt2: 6 prescribed proofs from the
                   article, the 8 shared directions, optional scope arm
generate_pythagoras.py
                   the same design on the Pythagorean theorem: 6 prescribed
                   proofs, the 8 shared directions, a generalisation ladder
                   for scope
prune.py           drops records whose stored prompt no longer matches what
                   the generator would send, so --submit can refill the
                   cell. The generators resume by id and cannot notice a
                   wording change on their own
embedding.py       embeds with bge-m3 → embeddings/<theorem>.npy, and
                   draws the UMAP figures. The only file that loads the
                   model, and the only one needing sentence-transformers,
                   umap-learn or matplotlib. Cache-first: if the .npy
                   exists and its row count matches, the model is never
                   loaded. The cache name is derived from the corpus name,
                   so the two cannot be mismatched
lookup_tables.py   the strings the analysis matches against: the
                   registries of named external results (one per theorem),
                   mathematicians' surnames in six languages, and the
                   technique-diagnostic notation. Data only -- imported by
                   analyse.py, imports nothing back
analyse.py         every analysis stage, in one run, off the cached
                   embeddings. Nothing here embeds anything:
                     1 lengths       integrity, raw and normalised lengths,
                                     direction vs language separation, CJK
                                     × direction interactions, centre cell
                     2 probes        leave-one-language-out probe on
                                     technique
                     3 structure     language/style/technique spectra,
                                     subspace angles + nulls, centroid
                                     agreement, hard probes, lexical
                                     baseline, style slices, cross-lingual
                                     transfer, extremal ranking
                     4 extreme       classify the extreme arm against the
                                     technique centroids; assignment
                                     confidence, out-of-set threshold,
                                     direction × technique + permutation
                                     null, the scope test
                     5 ablation      mask discriminative vocabulary,
                                     re-embed, and compare cross-lingual
                                     transfer to the unmasked space
                                     (primes only; ablation.py)
ablation.py        stage 5: writes masked corpora, embeds, and prints
                   unmasked vs masked transfer matrices

WRITEUP.md         the write-up

proofs_primes.jsonl                     the corpus, 558 records
proofs_primes.pre-generality-fix.jsonl  pre-fix corpus, kept as provenance
embeddings/primes.npy                   bge-m3 embeddings (558 × 1024),
embeddings/sqrt2.npy                    regenerable; one cache per corpus,
embeddings/pythagoras.npy               named by embedding.py
pilot_umap_raw.png
pilot_umap_centred.png
```

One corpus and one embedding cache per theorem, named alike:
`proofs_<theorem>.jsonl` and `embeddings/<theorem>.npy`. They are kept
apart rather than pooled because the analysis estimates language means from
the corpus it is given, and a Pythagoras proof is not evidence about how
Chinese renders a proof about primes.

## Running it

```bash
uv sync
export ANTHROPIC_API_KEY=...        # or put it in secrets.env

uv run generate_primes.py --dry-run # print the grid, no API calls
uv run generate_primes.py --submit  # submit the batch
uv run generate_primes.py --collect # poll and write proofs_primes.jsonl

uv run analysis/embedding.py        # downloads bge-m3 (~2GB), embeds, UMAPs
uv run analysis/analyse.py          # the whole analysis, no arguments
```

`analyse.py` takes no options. It runs all three theorems, all seven
stages and both masking tiers in about two minutes, because it never
loads the model — so there is nothing worth configuring, and no way to
produce a number by passing a flag rather than editing the file. What
differs between theorems is a table of constants at the top of it.

`embedding.py` is the slow half, once: it is cache-first, so a second run
loads no model at all. Run it per corpus, including the masked corpora
that `analyse.py` writes.

Everything after `generate_primes.py` reads the cached embeddings and makes
no API calls. Runs on a laptop; no GPU needed.

## The other two theorems

`generate_sqrt2.py` runs the same design on the theorem Conway and Shipman
actually wrote about, and `generate_pythagoras.py` on the theorem with the
most known proofs. Both corpora are generated: 696 records for sqrt2 and
678 for Pythagoras, against 558 for primes.

```bash
uv run generate_sqrt2.py --dry-run  # 600 proofs; --scope-arm adds 126
```

| arm | n | grid |
|---|---|---|
| technique | 360 | 6 techniques × 6 languages × 2 styles × 5 samples |
| extreme | 240 | 8 directions × 6 languages × 5 samples |
| scope | 126 | 7 statements × 6 languages × 3 samples (opt-in) |

Three things this theorem has that the infinitude of primes did not.

**Generality becomes checkable.** Conway and Shipman document each proof's
*scope* — the set of numbers it settles — and use differing scope as their
test for whether two proofs are really different. Covering does √2 and √3;
folding does √(n²±1); the traditional parity proof does roots of primes;
reciprocation does square roots of every nonsquare; unique factorisation
does all roots of all integers; the analytic proof does all algebraic
integers. So the generality axis has a ground-truth ordering, which on the
primes theorem it did not.

**Visuality gets more than one target.** The primes corpus could not tell
its three visual proofs apart and that axis died. Here there are two
geometric arguments the article itself separates — covering is "visually
obvious", folding "purely geometrical" — so which one the prompt selects is
a question with an answer.

**The instrument is deliberately harder.** The article calls covering and
folding "mechanically the same". Expect the technique probe below the 1.000
the primes arm reached; five obviously distinct arguments were an easy test.

The scope arm asks for a proof of a *different* statement (√3, √6, √7, √17,
∛2, and the root of x³ = x+1) with no selection criterion, so scope is
measured by what the model produces at each boundary rather than by asking
it to describe its own proof — a question that caused the truncations noted
above. It carries no criterion at all, so it is also the missing baseline:
what the model writes unprompted. Bashmakova's mod-8 proof, the seventh in
the article, is left out because for N = 2 the article says it is really the
traditional proof.

**The primes corpus has the same arm**, added afterwards so the two
theorems are analysed on the same footing (`generate_primes.py --scope-arm`,
108 records, not generated yet). The ladder is not indexed by a number
there, which is what made it easy to miss: primes ≡ 3 mod 4, where Euclid's
argument adapts directly; ≡ 1 mod 4, still Euclidean but needing an extra
input; ≡ 2 mod 5, where **no** Euclidean proof exists — Murty's 1988 result
is that one exists for *a* mod *q* exactly when a² ≡ 1 mod q, and 4 ≢ 1 mod
5 — the divergence of Σ1/p, which only the counting arguments reach; and an
effective bound, which Fürstenberg cannot give at all. Its first cell is the
theorem itself with no criterion: the interior point the 450-record corpus
never had.

### The Pythagorean theorem

```bash
uv run generate_pythagoras.py --dry-run   # 600 proofs; --scope-arm adds 108
```

Techniques: Euclid I.47, similar triangles, the dissection, Garfield's
trapezoid, Ptolemy, inner product. Two pictures of different kinds, two
computations, one quoted named theorem, one that abandons the triangle.

This is the theorem where **visuality is the default rather than an exotic
corner**, which is the axis that died on the primes corpus. Its scope arm is
a generalisation ladder rather than a list of harder cases: law of cosines
(drop the right angle), the box diagonal (add a dimension), de Gua (areas
instead of lengths), the parallelogram law and the inner-product statement
(drop geometry altogether). Each rung kills a different family of proofs.

Two caveats specific to it. **Circularity**: the famous wrong proof derives
the theorem from sin²+cos²=1, which *is* the theorem, and nothing in the
pipeline checks correctness — the `surprise` and `machinery` directions need
hand-reading. **Coverage**: Loomis catalogued 371 proofs, so six centroids
cover far less of the known space than five did for primes, and
stage 4's out-of-set threshold is correspondingly weaker evidence here.

Also, two of the seven direction prompts could not be carried over verbatim.
`elementarity` says "assume nothing beyond the definition of divisibility",
which is the right floor for primes and √2 and irrelevant to areas;
`constructiveness` asks for "a strictly simpler representation", which is
the √2 descent. Both were adapted, and the file records it. So
brevity/generality/visuality/machinery/surprise stay comparable across all
three theorems, elementarity across primes and √2 only, and
constructiveness not across theorems at all.

### Where the scope arm is read

Held out of every *estimate* — language means, the within-language length
baseline, the technique centroids. Those have to come from proofs of one
theorem, and a ∛2 proof is not evidence about how Japanese renders a √2
proof. Being unfit to estimate from is not the same as being unfit to
classify, and classifying it is the point:

- `analyse.py` stage 4 §9 — the scope test. Each target is classified against the
  technique centroids: which known argument does the model reach for as the
  statement moves out of each proof's documented scope, and do the records
  drift past the out-of-set threshold when it moves out of all of them.
- `analyse.py` stage 1 §5 — the centre cell against each direction on the
  normalised length scale. A direction is only extreme relative to what the
  model writes unprompted, and that reference point did not exist before.
- `graphs.py` fig6 — invoked results per target (registry lookup on stage 1
  lengths), testing whether dependence climbs as the statement leaves the
  light arguments behind.

Every figure reported above is unaffected by generating any of it, verified
by diffing all five stages' output before and after, not assumed.

The registries in lookup_tables.py keep one list of named results per theorem, chosen
from the corpus's own `theorem` field, and stops rather than falling back
when it meets a theorem it has no registry for. The √2 and Pythagoras
registries print a PROVISIONAL banner: they were built from the literature
rather than derived from a corpus, so a low count from them may be a missed
name rather than a proof invoking nothing. The scale of that failure, if it
went unguarded: the √2 registry run against the primes corpus reports 0.85
invoked results where the right one reports 16.63.

## What's actually in the analysis

Ordered by what survived.

**Held.** Language is additive and removable — subtracting each language's
mean embedding takes the same-technique/cross-language cosine gap from
+0.012 (a tie) to +0.378, and drops a language probe from 1.000 to 0.013
while technique classification stays at 1.000. Identical under leave-one-out
means, so not an artefact of in-sample centring. This is a replication of
[Libovický et al. 2020](https://arxiv.org/abs/2004.05160), which I found
after the fact.

**Held.** The extreme-arm direction × technique mapping (χ² = 365.5,
Cramér's V = 0.781; permutation null over direction labels puts p < 1/20000,
against a null mean of 16.1). Identical in all six languages for brevity,
elementarity and generality; machinery and visuality vary at the edges.

**Did not hold.** Near-orthogonal principal angles between the factor
subspaces (min 78.9°). A permuted-label null lands at 77.0° (p = 0.86) and a
random-subspace null at 83.0° — the angle measures the dimensionality, not
the design.

**Did not hold.** "Technique structure survives translation" as a claim
about argument structure. A within-English TF-IDF baseline (word bigrams,
style held out) hits 0.940 against the embedding's 0.980 — technique
identity is largely lexical.

**Did not hold.** "Four of five directions leave the reference set,"
inferred from an out-of-set cosine threshold. Reading twelve proofs showed
only `machinery` does; the rest are out-of-*register*, not out-of-set.

**Held, and it fixes the main error.** A non-lexical second coordinate
(fig6 / registry lookup): the count of distinct named external results a proof
invokes. It separates the machinery arm from Fürstenberg at accuracy 1.000
(16.63 against 0.32 invoked results) where the embedding merged them, and it
survives a length-matched control — the longest 30 technique-arm records are
*longer* than the machinery proofs and invoke 1.43.

The nulls and baselines are the point. `angle_null` and `lexical_baseline`
in stage 3 each take about ten seconds and each killed a headline.

**Held, and it answers an open question.** Cross-lingual technique transfer
on *uncentred* bge-m3 (stage 3 §11): en→zh 0.900, en→ja 0.920, against
0.62 and 0.50 on the earlier 768-dim encoder. The transfer gap was the
encoder, not the centring.

**Known failing check.** Stage 4 section 1 tests whether language means
estimated on the technique arm remove language from the extreme arm. They do
not — the probe sits at 0.487 against chance 0.167. The extreme-arm result
therefore rests on the mapping being identical across all six languages,
not on clean out-of-sample language removal.

## Is the technique signal lexical?

Stage 3 section 9 gives the number that raises the question: within
English, TF-IDF word 1-2grams recover the technique at **0.940** against a
chance of 0.200, where bge-m3 manages **0.980**. A bag of words comes within
four points of the encoder. That is consistent with the encoder reading
arguments *and* with it reading only vocabulary, and section 9 cannot tell
the two apart.

Stage 5 separates them by taking the vocabulary away. Three results, in
the order they were found.

**Named machinery is not the give-away.** Masking every entry in the
registry, every mathematician's name in six languages, and
every technique-diagnostic symbol moves the lexical baseline by *nothing* —
0.940 before, 0.940 after. Only 1–7 terms per proof are affected and 212 of
558 records contain no match at all. Whatever identifies a technique, it is
not the citations.

**It is the ordinary descriptive vocabulary, and it is diffuse.** Selecting
terms by classifier weight instead (the `discriminative` tier, terms
chosen on terse records and tested on verbose, so the selection never sees
the test side):

| top-k masked | TF-IDF | text kept | example terms |
|---|---|---|---|
| 0 | 0.960 | 0.990 | (registry tiers only) |
| 10 | 0.800 | 0.992 | mathcal, sum_, sqrt |
| 25 | 0.640 | 0.984 | squarefree, subseteq, mathcal |
| 100 | 0.400 | 0.943 | representation, squarefreeness, factorization |
| 400 | **0.200** | 0.865 | longrightarrow, distributivity, representation |

A slope, not a cliff. No small set of keywords carries the label; it takes
roughly 400 word types before a bag of words is at chance, and 86% of the
text is still on the page when it gets there. This is the ambiguous outcome
and worth stating as such: an argument and the words used to state it are
not separable in prose, so a gentle decay is as consistent with the encoder
tracking the mathematics as with it tracking diffuse wording.

**Are the hand-written lists any good?** Stage 6's audit section checks them
against the corpus instead of asserting them, using the fact that the same
mathematics is written six times: an entry that fires in every language at a
similar rate is working, and one that fires in a single language is wrong in
one of two opposite ways. It found both kinds.

- *A collision.* `Tales` is Thales in Spanish and also the ordinary Spanish
  word for "such". It took 24 hits in the Spanish primes proofs — `enteros m
  tales que m² | n` — and not one was Thales. The mask was deleting a
  function word. Fixed by requiring `Tales de Mileto`.
- *A coverage gap.* On Pythagoras, `area_axioms` fires only in Chinese (剪拼)
  and `trig_identity` only in English ("Pythagorean identity"). Both matches
  are genuine; what is missing is the other five languages' phrasings. The
  fix is to add forms, not remove one.

The counts cannot tell those apart, so the audit prints an excerpt from each
flagged entry and declines to give a verdict. An earlier version labelled all
of them "likely false positives", which was wrong for two of the three.

For the machinery tier this matters more on √2 and Pythagoras, whose
registries lookup_tables.py marks provisional (`VALIDATED` holds only
`infinitude_of_primes`). It matters least where it counts: the headline
result uses the discriminative tier, which reads no list at all.

**The hole does not leak.** Every masked term becomes the same placeholder,
so the corpus does not record which term was removed. Classifying technique
from what a reader of the masked text *can* see — placeholder count, length,
density — sits at chance (0.200). An earlier version of this check used
per-term counts and reported a leak of 0.90; that was the check classifying
from its own mask log rather than from the proofs, and it is now restricted
to observable features.

The masked corpora are cut at the point where the lexical baseline is dead:
400 terms per language for primes and √2, 800 for Pythagoras, whose
vocabulary is more redundant and still sits at 0.433 after 400. That is
the `TOPK` table at the top of `analyse.py`.

```bash
# stage 5 writes the masked corpus, embeds, and prints transfer matrices
uv run analysis/ablation.py
```

Or as the last step of a full analyse.py run (primes only):

```bash
uv run analysis/analyse.py
```

The open question it answers: on a corpus where TF-IDF is at
chance, does bge-m3 still recover the technique? If it does, something
beyond vocabulary is being represented. If it falls with the words, the
technique geometry in this report is a lexical artefact — and the
cross-lingual transfer in stage 3 §11 was proper-noun alignment.

## Caveats

One theorem, one generator, two embedding models that disagree on
cross-lingual transfer. Proof correctness is unverified beyond twelve
records read by hand. Everything here is a fact about one model's
organisation of proof-writing, not about proofs.
